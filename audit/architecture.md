# Architecture and audit scope

JDSH is a Python CLI/TUI for JDownloader 2. The invoking OS user is the application principal. `jd` and `python -m jdsh` dispatch to the same CLI. JDSH connects to the configured MyJDownloader direct/local API endpoint; it does not implement an app server or tenant model. The default endpoint is `127.0.0.1:3128` (`src/jdsh/config.py:13-20`, `src/jdsh/client.py:111-125`).

The principal's intended authority includes reading queue/link/package state, adding links, confirming pending packages, removing/replacing links, checking availability, and starting/stopping downloads (`src/jdsh/cli.py:253-327,383-421,593-640`). The strongest boundary is the JDownloader API and its network exposure/authentication. JDSH delegates that boundary to `myjdapi`; JDownloader project manager guidance says the deprecated API lacks authentication/encryption by default, while repository source does not establish deployed bind/firewall settings. README setup explicitly documents enabling the deprecated Local API and mentions disabling localhost-only mode for remote use (`README.md:20-25`).

Entry surfaces include CLI arguments and a user-selected input file (`src/jdsh/cli.py:658-715`), macOS clipboard HTML/plain text (`src/jdsh/clipboard.py:44-60,120-137`), a home-directory config file (`src/jdsh/config.py:13-20`), and API response data. URL strings flow to JDownloader LinkGrabber after comma joining (`src/jdsh/cli.py:593-611`). API results flow to Rich terminal output or JSON (`src/jdsh/cli.py:202-250,289-327,532-590`; `src/jdsh/tui.py:52-162`). Clipboard commands use fixed executable arguments, no shell, and a five-second timeout (`src/jdsh/clipboard.py:63-95`).

The project uses Python >=3.8, `rich`, `myjdapi`, and Hatchling (`pyproject.toml:1-17`); no lockfile is tracked. The release workflow publishes on release or manual dispatch, grants PyPI OIDC identity permission, and does not run tests (`.github/workflows/release.yaml:3-26`). These are supply-chain hardening observations, not demonstrated vulnerabilities. README names the config file `jdsh.config`, while source reads `jdsh.conf` (`README.md:95-108`, `src/jdsh/config.py:13-20`).

Quick-profile source review covered injection, access control, resource/file handling, secrets, business logic, feature/data leakage, chained trust boundaries, wildcard, and obvious exposures across the coarsened repository subsystem. A fresh verifier retained the remote Local API lead as needs validation because deployed reachability remains unknown. The coverage critic also flagged Rich-rendered API strings, response-size/polling behavior, and URL forwarding for future bounded validation; no concrete boundary violation was established for those paths from source.

Execution was blocked because the environment does not expose the OS-enforced sandbox required by the audit skill. No project code, build, tests, browser, or live endpoint was executed. Accordingly, the run is incomplete and makes no complete-coverage claim.
